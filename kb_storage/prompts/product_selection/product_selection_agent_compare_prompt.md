## Цель

Сравнить ровно два продукта по строкам успешного `execute_sql`.
Коды бери только из `product_resolutions`. Не резолви названия сам.

## Tools

`search_column`, `execute_sql`.
Не вызывай `search_semantic_template` / `search_objects` / `search_analytic` для этого сценария.

## Алгоритм

1. Из `product_resolutions.items` возьми уникальные `product_code` со status resolved.
2. Если кодов не ровно 2:
   - есть варианты → `needs_clarification`;
   - иначе → `no_data`.
3. Опционально `search_column("products")`.
4. `execute_sql`:
   ```sql
   SELECT <все подтвержденные свойства>
   FROM products
   WHERE code IN ('code1', 'code2')
   ```
5. Нужны 2 строки. Если успешный SQL уже вернул 2 строки — сразу JSON, не повторяй тот же SQL.


## SQL

- `code` всегда строковый литерал.
- Для compare бери полный набор свойств продуктов, не короткий `display_columns`.
  Минимум колонки: `code`, `name`, `is_active`, `insurance_type`, `product_type`, `term`,
  `capital_loss_risk`, `product_risk_level`, `income`, `contribution_type`, `payout_type`,
  `liquidity`, `currency`, `fx_protection`, `segment`, `client_goal`, `taxes`, `tax_benefits`,
  `in_focus`, `in_focus_condition`, `input_date`, `commission`
- Не используй `SELECT *`.
- Повторный `execute_sql` только с измененным SQL после ошибки / неполного результата.

## message
Отличающиеся свойста идут в блоке каждого продукта, одинаковые свойства в блоке `Одинаковые свойства:`
На русском, структура:

```
<code1> - <name1>
- отличающееся свойство: значение
...

<code2> - <name2>
- отличающееся свойство: значение
...

Одинаковые свойства:
- одинаковое свойство: значение
- одинаковое свойство: значение
```

- в навзваниях свойств используй русские названия, а не имена полей из БД
- КВ (`comission`) указывай в процентах, а не долях, после числа ставь знак `%` 
- все различающиеся свойства должны быть в блоках обоих продуктов
- если отличающихся свойств нет, под каждым продуктом напиши `• отличающиеся свойства по найденным данным не выявлены`;
- если одинаковых свойств нет, в блоке `Одинаковые свойства:` напиши `• одинаковые свойства по найденным данным не выявлены`;
- проверь, что в ответе нет шаблонных плейсхолдеров, технических маркеров или незамененных переменных.

- В message обязательно включи следующие свойства `Действующий`, `Тип страхования`, `Тип продукта`, `Срок`,
  `Риск потери капитала`, `Уровень риска продукта`, `Доход`, `Тип взноса`, `Тип выплат`, `Ликвидность`,
  `Валюта`, `Защита от девальвации рубля / аллокация на валюту`, `Сегмент`, `Цель клиента`, `Налоги`,
  `Налоговые преференции`, `В фокусе`, `КВ`
- не включай поле если оно пустое


Все свойства из SQL должны быть в ответе (в блоках продуктов или в «Одинаковые свойства»).
Заполни `products_json` JSON-массивом из двух объектов SQL с полями `code` и `name` (не `product_code` / `canonical_name`).
`used_tables` = `products` (строка, не массив).
Схема ответа плоская: без вложенных объектов; списки только в `*_json` строках.

Важно для output_schema:
- `status` всегда `ok`;
- при уточнении `mode=needs_clarification`, а не `product_compare`;
- в `clarification_options_json` каждый объект: `{"code":"...","name":"..."}`.
