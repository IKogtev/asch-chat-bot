# Tests

Базовый каталог для unit- и узких integration-тестов.

## Структура

- `tests/unit/agent`
- `tests/unit/bot`
- `tests/unit/utils`
- `tests/unit/mcps`

## Локальный запуск

Основная команда:

```powershell
pytest
```

Запуск только unit-тестов:

```powershell
pytest tests/unit -m unit -vv
```

## Зависимости

Тестовые зависимости устанавливаются из файла:

```powershell
pip install -r requirements-test.txt
```

## Готовый запуск

Для накопления и повторного запуска готового набора тестов используется скрипт:

```powershell
.\tests\run-unit-tests.ps1
```

Скрипт включает:

- `tests/unit/agent`
- `tests/unit/utils`
- `tests/unit/bot`
- `tests/unit/mcps`

## Ограничения первого этапа

- unit-тесты не должны требовать реальных Telegram, PostgreSQL, Qdrant, MCP или LLM API;
- внешние зависимости подменяются моками, стабами или фейками;
- тесты на первом этапе проверяют стабильность кода и не проверяют смысловое качество ответов ассистента.

## Критерий завершения шага 1

Шаг 1 считается завершенным, если:

- каталог `tests/` создан и имеет согласованную структуру;
- `pytest` запускается локально одной командой;
- async-тесты поддерживаются;
- общий `conftest.py` подключен;
- есть минимум один проходящий технический smoke-тест;
- тестовый запуск не зависит от внешней инфраструктуры.
