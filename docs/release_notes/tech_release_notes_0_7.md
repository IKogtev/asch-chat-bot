# Технические release notes 0.7

Изменения по сравнению с релизом 0.6.6:

1. Добавили нового агента `product_selection_agent` для сценариев подбора, фильтрации, сравнения, рекомендаций и объяснения продуктов.
2. Добавили новый MCP `dbhub` для read-only доступа агента к PostgreSQL через инструменты `search_table`, `search_column`, `search_analytic`, `search_semantic_template`, `search_objects` и `execute_sql`.
3. Добавили новую базу данных `nstya_data` в PostgreSQL для табличных продуктовых данных и data catalog.
4. Добавили конфигурацию `mcps/dbhub/dbhub_nstya_config.toml`; при разворачивании нужно примонтировать ее в контейнер `dbhub`.
5. Добавили сервис `dbhub` в `docker-compose.yaml`; он зависит от `postgres` и публикует MCP endpoint `http://dbhub:8080/mcp`.
6. Добавили переменные окружения для подключения агента к `dbhub`: `DBHUB_MCP_URL`, `DBHUB_MCP_TOKEN`, `DBHUB_MCP_TIMEOUT_SEC`.
7. Добавили загрузчик таблиц в `nstya_data`: скрипт `load_tables.ps1` запускает `python -m app.scripts.load_tables` внутри контейнера `kb-manager`.
8. Добавили переменные окружения `kb-manager` для загрузчика таблиц: `NSTYA_DATA_URL` и `NSTYA_DATA_SOURCE_DIR`.
9. Добавили правило загрузки Excel-файлов: обрабатываются только файлы с суффиксом `_active.xlsx`; суффикс удаляется при формировании имени таблицы.
10. Добавили обязательный файл data catalog `business layer_active.xlsx`; из него создаются таблицы `dc_entities`, `dc_columns`, `dc_analytics`, `dc_semantic_templates`.
11. Добавили поддержку второй строки-комментария в Excel-файлах: если первая ячейка строки содержит `#`, строка пропускается при загрузке.
12. Добавили Alembic-миграцию `b2c3d4e5f6a7_add_events_table.py` для таблицы `events`; перед запуском новой версии нужно применить миграции.
13. Добавили ORM-модель `LoggedEvent`; создание таблицы `events` больше не выполняется автоматически в runtime через `EventLogger`.
14. Добавили настройки сжатия контекста агента: `AGENT_CONTEXT_COMPACTION_INTERVAL`, `AGENT_CONTEXT_COMPACTION_OVERLAP_SIZE`, `AGENT_CONTEXT_TOKEN_THRESHOLD`, `AGENT_CONTEXT_EVENT_RETENTION_SIZE`.
15. Добавили prompt-файл `kb_storage/prompts/product_selection/product_selection_agent_prompt.md`; при разворачивании нужно сохранить монтирование `kb_storage/prompts` в контейнер агента.
16. Обновили dispatcher: появился маршрут `product_selection`, который направляет продуктовые запросы в нового агента.
17. Обновили экспорт диалогов в `kb-manager`: выгрузка теперь связывает сообщения, ответы и скачанные файлы по `turn_id`, а время ответа выводится в секундах.
18. Добавили вспомогательный скрипт `tests/create_session_adk_web.ps1` для создания сессии через ADK Web API.
19. Добавили и обновили unit-тесты для нового агента, маршрутизации, сжатия контекста и загрузчика таблиц.

Дополнительные изменения из `release_notes_max_global_user.md`:

20. Был добавлен чат-бот для платформы макс повторяющий всю функциональность телеграм бота который был отдельным контейнером, впоследствии была произведена унификация, чтобы мы могли менять код только в 1 месте и он сразу работал на двух ботов разных реализаций.
21. Было добавлено глобальное состояние пользователя и глобальные пользователи, теперь у нас 1 человек= 1 номер телефона глобальный пользователь, пользователь может иметь много аккаунтов, и например начать диалог на 1 платформе а продолжить на другой.
22. Для filegator сделана безопасность, теперь посмотреть просто файлы без авторизации нельзя, только с авторизацией.
23. Добавлена возможность через глобальную переменную задавать интервал на время переиндексации.
24. Группы пользователей изменены (добавлена возможность блокировки и разблокировки пользователей, теперь они отображаются там на основе глобального id, можно посмотреть id аккаунтов пользователей, нажав на кнопку id) при событии разблокировки реализовано уведомление
25. Исправлен баг в UI с подсчетом собщений в неделю(раньше делил на 7 всегда, теперь высчитывается по умному количество недель, из выбранного промежутка)
26. Исправлено отображение диалогов по пользователям, пользователи скачавшие документ отображаются теперь в виде таблицы
27. Везде в диалогах добавлена платформа, чтобы понимать на какой платформе было написано  сообщение.
28. Сделаны соответствующие alembic миграции в БД, добавлен сервис для миграций

Минимальный порядок действий при обновлении:

1. Обновить образы и конфигурацию сервисов до версии 0.7.
2. Проверить, что в окружении заданы `DBHUB_MCP_URL`, `DBHUB_MCP_TOKEN`, `DBHUB_MCP_TIMEOUT_SEC`, `NSTYA_DATA_URL`, `NSTYA_DATA_SOURCE_DIR`.
3. Запустить PostgreSQL и применить Alembic-миграции, включая создание таблицы `events`.
4. Запустить сервис `dbhub` и проверить доступность MCP endpoint `/mcp`.
5. Подготовить Excel-файлы в каталоге `NSTYA_DATA_SOURCE_DIR`: продуктовые таблицы должны иметь суффикс `_active.xlsx`, data catalog должен называться `business layer_active.xlsx`.
6. Загрузить таблицы в новую базу командой `.\load_tables.ps1`.
7. Перезапустить `adk-agent` и `adk-web`, чтобы агент подхватил новый prompt и MCP-настройки.
