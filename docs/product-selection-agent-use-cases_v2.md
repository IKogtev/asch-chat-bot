# Агент подбора продуктов: сценарии использования

Дата подготовки: 28.04.2026  
Источник: `Классификатор 27.04.26.xlsx`, лист `Лист1`, 26 продуктовых строк.

## 1. Цель документа

Документ описывает упрощенный набор сценариев использования ассистента подбора продуктов на базе продуктового классификатора.

Ассистент должен помогать менеджеру быстро находить карточку продукта, выдавать комплект материалов, фильтровать продукты по параметрам и сравнивать продукты между собой. Ассистент не должен подменять финальное решение менеджера и комплаенс-проверки.

## 2. Основные типы запросов

| Тип запроса | Примеры | Ожидаемое действие |
|---|---|---|
| Карточка продукта | "Какие основные свойства продукта 2832?", "Расскажи про Fort Knox 6 месяцев" | Найти продукт и вывести ключевые свойства |
| Комплект продукта | "Дай комплект для продукта 2832" | Найти папку продукта в `kb_storage` и загрузить пользователю все файлы из нее |
| Фильтр по параметрам | "Какие есть краткосрочные продукты?", "Покажи продукты без риска потери капитала" | Вернуть таблицу продуктов с основаниями отбора |
| Сравнение | "Сравни Защищенный капитал и Fort Knox" | Построить таблицу различий и сходств |

Продукт может определяться по ID, точному названию, частичному названию или алиасу.

Алиас продукта - это сокращение в отдельном столбце исходной таблицы. Например, `ЗК` - сокращение для группы продуктов "Защищенный капитал".

Алиас не уникален. Это не идентификатор конкретной строки, а "кличка" группы продуктов. Если по алиасу находится несколько продуктов, ассистент должен показать варианты и попросить уточнить срок, валюту или конкретную версию.

## 3. Детальные use cases

### UC-01. Получить карточку продукта

**Цель:** быстро ответить на вопрос о свойствах конкретного продукта.

**Примеры запросов:**

- "Какие основные свойства продукта 2832?"
- "Основные параметры Защищенный капитал 5 лет"
- "Расскажи про Fort Knox 6 месяцев"

**Основной сценарий:**

1. Найти продукт по ID, точному названию, частичному названию или алиасу.
2. Если найдено несколько вариантов, показать список и попросить уточнить срок, валюту или конкретную версию.
3. Вывести карточку продукта по данным классификатора.

**Требования к формату ответа:**

- карточка должна хорошо смотреться в Telegram;
- использовать `bold` для названия продукта и ключевых заголовков;
- использовать `italic` для пояснений, ограничений и источника данных;
- не перегружать ответ: показывать только ключевые свойства продукта;
- отделять данные классификатора от вывода ассистента.

**Рекомендуемая структура карточки:**

- **Название продукта**
- **ID**
- **Тип страхования**
- **Тип продукта**
- **Срок**
- **Риск потери капитала**
- **Уровень риска**
- **Доход**
- **Взнос и выплата**
- **Ликвидность**
- **Валюта**
- **Цель клиента**
- *Источник: версия классификатора*

**Пример по текущей таблице:** для `Fort Knox 6 месяцев` ассистент должен показать: НСЖ, квазидепозит, краткосрочный срок, без риска потери капитала, низкий риск, гарантированный доход, единовременный взнос, единовременная выплата, высокая ликвидность, рубли, цель "заработать / приумножить".

### UC-02. Получить комплект продукта

**Цель:** менеджер запрашивает полный комплект материалов по продукту.

**Пример запроса:** "Дай комплект для продукта 2832".

**Входные данные:**

- ID продукта, название или алиас.

**Хранение комплекта:**

- в `kb_storage` есть отдельная подпапка для комплектов продуктов;
- внутри этой подпапки папки называются кодом продукта;
- в папку продукта складываются все файлы комплекта для данного продукта;
- при запросе комплекта ассистент загружает пользователю все файлы из папки найденного продукта.

**Основной сценарий:**

1. Ассистент определяет продукт по ID, названию или алиасу.
2. Если не удается однозначно определить продукт, показывает список вариантов и просит уточнить продукт.
3. Находит папку продукта в `kb_storage` по коду продукта.
4. Загружает пользователю все файлы из папки продукта.
5. Если папка продукта пуста, сообщает, что комплект для продукта пока не загружен.

**Исключения:**

- ID или название не найдены: попросить уточнить продукт или показать похожие варианты.
- По алиасу найдено несколько продуктов: попросить выбрать конкретный продукт.
- Папка продукта не найдена: сообщить, что комплект для продукта отсутствует.
- В папке нет файлов: сообщить, что комплект для продукта пока не загружен.

### UC-03. Найти продукты по параметрам

**Цель:** вывести список продуктов, соответствующих фильтрам пользователя.

**Примеры запросов:**

- "Какие есть краткосрочные продукты?"
- "Покажи продукты с высокой ликвидностью"
- "Какие продукты без риска потери капитала?"
- "Есть продукты в юанях?"

**Основной сценарий:**

1. Распознать фильтры из запроса.
2. Применить фильтры к классификатору.
3. Вернуть список продуктов с краткими основаниями отбора.
4. Если результатов нет, сообщить об этом и предложить ослабить критерий.
5. Если пользователь сказал "сегодня", указать версию данных и не утверждать актуальность, если в классификаторе нет статуса актуальности.

**Требования к формату ответа:**

- результат фильтра должен выводиться таблицей;
- таблица должна хорошо смотреться в Telegram;
- выбирать только нужные колонки, без лишних внутренних полей;
- значения в ячейках должны быть короткими;
- если продуктов много, показывать основные совпадения и писать, что список сокращен.

**Рекомендуемые колонки таблицы:**

| Продукт | Срок | Риск | Доход | Ликвидность | Валюта |
|---|---|---|---|---|---|

### UC-04. Сравнить продукты или группы продуктов

**Цель:** дать менеджеру таблицу сравнения и краткий вывод.

**Пример запроса:** "Сравни продукты Защищенный капитал и Fort Knox".

**Основной сценарий:**

1. Определить, идет речь о конкретных продуктах или группах продуктов.
2. Если название или алиас неоднозначны, предложить варианты: например, `Защищенный капитал 2 года`, `Защищенный капитал 5 лет`, валютные версии.
3. Получить значения по ключевым полям классификатора.
4. Построить таблицу сравнения.
5. Сформулировать краткий вывод: когда какой продукт уместнее.

**Требования к формату ответа:**

- сравнение должно выводиться таблицей;
- таблица должна хорошо смотреться в Telegram;
- в строках таблицы должны быть параметры сравнения, в колонках - сравниваемые продукты или группы продуктов;
- длинные пояснения выносить в краткий вывод после таблицы;
- если сравниваются группы продуктов, явно указать, что значения могут отличаться внутри группы.

**Пример логики для текущего классификатора:**

| Параметр | Fort Knox | Защищенный капитал |
|---|---|---|
| Тип страхования | НСЖ | НСЖ |
| Тип продукта | Квазидепозит | Квазидепозит |
| Сроки | 6 месяцев, 9 месяцев, 1 год, 3 года и бандлы | 2 года, 5 лет, 3 года в долларах или юанях |
| Риск потери капитала | Без риска | Без риска |
| Уровень риска | Низкий | Низкий |
| Доход | Гарантированный | Гарантированный |
| Ликвидность | От высокой до низкой, зависит от срока | Низкая |
| Валюта | Рубли | Рубли, доллары, юани |
| Защита от девальвации | Нет | Есть у валютных версий |
| Налоговые преференции | Нет в строках Fort Knox | Есть у версии на 5 лет |

## 4. Логика обработки запроса

Базовый алгоритм:

1. Распознать намерение: карточка, комплект, фильтр или сравнение.
2. Извлечь сущности: продукт, ID, алиас, срок, валюта, риск, ликвидность.
3. Разрешить неоднозначности через ID, название, алиас и группу продуктов.
4. Для карточки вывести ключевые свойства продукта.
5. Для комплекта найти папку продукта в `kb_storage` и загрузить все файлы из нее.
6. Для фильтра применить условия к классификатору и вывести результат таблицей.
7. Для сравнения собрать значения ключевых полей и вывести результат таблицей.

## 5. Требования к ответам ассистента

Ответы должны быть короткими, проверяемыми и привязанными к данным:

- показывать основания отбора через поля таблицы;
- не скрывать неоднозначность;
- не утверждать актуальность "на сегодня", если в данных нет статуса актуальности;
- отделять данные классификатора от выводов ассистента;
- задавать уточняющие вопросы только когда без них меняется результат;
- не выводить внутренние поля во внешнем клиентском тексте;
- оформлять карточку продукта с использованием `bold` и `italic`, чтобы она хорошо смотрелась в Telegram;
- выводить результаты фильтра и сравнения таблицами, чтобы они хорошо смотрелись в Telegram.
