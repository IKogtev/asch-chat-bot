# Агент подбора продуктов: сценарии использования

Дата подготовки: 28.04.2026  
Источник: `Классификатор 27.04.26.xlsx`, лист `Лист1`, 26 продуктовых строк.

## 1. Цель документа

Документ описывает сценарии использования ассистента подбора продуктов на базе продуктового классификатора. Описание предназначено для согласования с Заказчиком и дальнейшего проектирования агента и его сервисов, включая работу с табличными источниками.

Ассистент должен помогать менеджеру быстро находить, сравнивать и объяснять продукты по параметрам из классификатора, а также подбирать подходящие варианты под цель клиента. Ассистент не должен подменять финальное решение менеджера и комплаенс-проверки.

## 2. Основные типы запросов

| Тип запроса | Примеры | Ожидаемое действие |
|---|---|---|
| Карточка продукта | "Какие основные свойства продукта 2832?", "Расскажи про Fort Knox 6 месяцев" | Найти продукт и вывести ключевые свойства |
| Комплект продукта | "Дай комплект для продукта 2832" | Собрать параметры, описание, презентацию, материалы акции |
| Фильтр по параметрам | "Какие есть краткосрочные продукты?", "Покажи продукты без риска потери капитала" | Вернуть список продуктов с основаниями отбора |
| Сравнение | "Сравни Защищенный капитал и Fort Knox" | Построить таблицу различий и сходств |
| Подбор под клиента | "Что посоветовать клиенту, который хочет сохранить сбережения?" | Уточнить профиль при необходимости, отобрать и ранжировать варианты |
| Объяснение выбора | "Почему ты предлагаешь этот продукт?", "Почему не Unit Linked?" | Объяснить решение через поля классификатора |
| Альтернативы | "Есть похожий продукт, но с большей ликвидностью?" | Найти близкие продукты с измененным ограничением |

## 3. Детальные use cases

### UC-01. Получить комплект продукта

**Цель:** менеджер запрашивает полный комплект материалов по продукту.

**Пример запроса:** "Дай комплект для продукта 2832".

**Входные данные:**

- ID продукта, название или алиас.
- При наличии: версия комплекта, канал продаж, дата актуальности.

**Основной сценарий:**

1. Ассистент определяет продукт по ID, названию или алиасу.
2. Получает строку классификатора и нормализованные свойства продукта.
3. Получает дополнительные материалы из источника продуктовых документов: описание, презентер, особенности акции, ссылки на файлы.
4. Проверяет актуальность материалов на дату запроса.
5. Формирует ответ: название продукта, краткое описание, ключевые свойства, список материалов и предупреждения по ограничениям.

**Ответ MVP:** если дополнительных материалов еще нет, ассистент выводит свойства из классификатора и сообщает, что описание, презентер и акции требуют подключения отдельного источника.

**Исключения:**

- ID не найден: попросить уточнить название или показать похожие продукты.
- Найдено несколько вариантов: попросить выбрать срок, валюту или конкретную версию.
- Материалы устарели: показать свойства продукта и отметить, что комплект требует обновления.

### UC-02. Получить карточку продукта / основные свойства

**Цель:** быстро ответить на вопрос о свойствах конкретного продукта.

**Примеры запросов:**

- "Какие основные свойства продукта 2832?"
- "Основные параметры Защищенный капитал 5 лет"
- "Расскажи про Fort Knox 6 месяцев"

**Основной сценарий:**

1. Найти продукт по ID, точному названию, частичному названию или алиасу.
2. Если найдено несколько вариантов, уточнить срок или валюту.
3. Вывести карточку продукта.

**Рекомендуемый формат ответа:**

| Блок | Содержание |
|---|---|
| Идентификация | Название продукта, ID, семейство продукта |
| Назначение | Цель клиента, сегмент |
| Финансовая логика | Срок, доход, тип взноса, тип выплат |
| Риск и ликвидность | Риск потери капитала, уровень риска, ликвидность |
| Валюта и налоги | Валюта, защита от девальвации, налоги, налоговые преференции |
| Источник | Версия классификатора и строка источника |

**Пример по текущей таблице:** для `Fort Knox 6 месяцев` ассистент должен показать: НСЖ, квазидепозит, краткосрочный срок, без риска потери капитала, низкий риск, гарантированный доход, единовременный взнос, единовременная выплата, высокая ликвидность, рубли, цель "заработать / приумножить".

### UC-03. Найти продукты по параметрам

**Цель:** вывести список продуктов, соответствующих фильтрам пользователя.

**Примеры запросов:**

- "Какие сегодня есть краткосрочные продукты?"
- "Покажи продукты с высокой ликвидностью"
- "Какие продукты без риска потери капитала?"
- "Есть продукты в юанях?"

**Основной сценарий:**

1. Распознать фильтры из запроса.
2. Применить фильтры к классификатору.
3. Отсортировать результат по согласованному правилу: точность совпадения, риск, ликвидность, срок, бизнес-приоритет.
4. Вернуть список с краткими основаниями отбора.
5. Если пользователь сказал "сегодня", указать версию данных.

**Пример результата по текущему классификатору для "краткосрочные продукты":**

| Продукт | Тип продукта | Срок | Риск | Доход | Ликвидность |
|---|---|---|---|---|---|
| Bundle Fort Knox 3+12 месяцев | Квазидепозит | Краткосрочный | Низкий | Гарантированный | Высокая |
| Bundle Fort Knox 6+12 месяцев | Квазидепозит | Краткосрочный | Низкий | Гарантированный | Высокая |
| Fort Knox 6 месяцев | Квазидепозит | Краткосрочный | Низкий | Гарантированный | Высокая |
| Fort Knox 9 месяцев | Квазидепозит | Краткосрочный | Низкий | Гарантированный | Средняя |
| Fort Knox 1 год | Квазидепозит | Краткосрочный | Низкий | Гарантированный | Средняя |

**Исключения:**

- Нет результатов: предложить ослабить критерий или показать ближайшие альтернативы.
- Фильтр не поддержан таблицей: сообщить, какого поля не хватает.

### UC-04. Сравнить продукты или семейства продуктов

**Цель:** дать менеджеру таблицу сравнения и краткий вывод.

**Пример запроса:** "Сравни продукты Защищенный капитал и Fort Knox".

**Основной сценарий:**

1. Определить, идет речь о конкретных продуктах или семействах.
2. Если название неоднозначно, предложить варианты: например, `Защищенный капитал 2 года`, `Защищенный капитал 5 лет`, валютные версии.
3. Получить значения по ключевым полям.
4. Построить таблицу сравнения.
5. Сформулировать краткий вывод: когда какой продукт уместнее.

**Пример логики для текущего классификатора:**

| Параметр | Fort Knox | Защищенный капитал |
|---|---|---|
| Тип страхования | НСЖ | НСЖ |
| Тип продукта | Квазидепозит | Квазидепозит |
| Сроки в классификаторе | 6 месяцев, 9 месяцев, 1 год, 3 года и бандлы | 2 года, 5 лет, 3 года в долларах или юанях |
| Риск потери капитала | Без риска | Без риска |
| Уровень риска | Низкий | Низкий |
| Доход | Гарантированный | Гарантированный |
| Ликвидность | От высокой до низкой, зависит от срока | Низкая |
| Валюта | Рубли | Рубли, доллары, юани |
| Защита от девальвации | Нет | Есть у валютных версий |
| Налоговые преференции | Нет в строках Fort Knox | Есть у версии на 5 лет |

### UC-05. Подобрать продукты под цель клиента

**Цель:** предложить варианты продуктов под потребность клиента и объяснить основания.

**Пример запроса:** "Какие продукты посоветовать клиенту, который хочет сохранить сбережения?"

**Основной сценарий:**

1. Извлечь цель клиента из запроса.
2. Определить обязательные критерии. Для цели "сохранить сбережения": без риска потери капитала, низкий риск, гарантированный доход.
3. Определить желательные критерии: ликвидность, срок, валюта, налоговые преференции.
4. Если данных не хватает, задать 1-3 уточняющих вопроса: горизонт, валюта, нужна ли высокая ликвидность.
5. Если можно ответить без уточнения, дать несколько групп вариантов.
6. Объяснить, почему продукты подходят и какие компромиссы есть.

**Пример ответа по текущему классификатору:**

| Ситуация клиента | Подходящие варианты | Почему |
|---|---|---|
| Нужен короткий горизонт и высокая/средняя ликвидность | Fort Knox 6 месяцев, Fort Knox 9 месяцев, Fort Knox 1 год, бандлы Fort Knox | Без риска потери капитала, низкий риск, гарантированный доход |
| Нужен более длинный срок и сохранение капитала | Защищенный капитал 2 года, Защищенный капитал 5 лет | Без риска потери капитала, низкий риск, гарантированный доход |
| Важна валютная защита | Защищенный капитал $ 3 года, Защищенный капитал ¥ 3 года | Валюта доллары/юани, есть защита от девальвации рубля |
| Клиент готов к инвестиционному риску | Unit Linked продукты можно рассмотреть отдельно | Есть риск потери капитала и доход не гарантирован, поэтому не основной вариант для цели сохранения |

### UC-06. Уточнить критерии при неоднозначном запросе

**Цель:** не угадывать важные параметры, если от них зависит ответ.

**Примеры неоднозначности:**

- "Защищенный капитал" может означать несколько сроков и валют.
- "Краткосрочные" понятно по таблице, но "выгодные" требует метрики выгоды.
- "Актуальные сегодня" требует статуса продукта.
- "Сохранить сбережения" может означать разные горизонты и валюту.

**Правило:** ассистент задает уточнение, если без него можно дать неверный или коммерчески рискованный ответ. Если безопасно дать обзор, ассистент дает обзор и отмечает допущение.

**Примеры уточнений:**

- "Уточните, пожалуйста: сравнить конкретный срок `Защищенный капитал 2 года/5 лет` или все семейство?"
- "Для подбора под сохранение сбережений важнее короткий срок, высокая ликвидность или валютная защита?"
- "Под 'выгодностью' сравниваем доход, налоговые преференции, ликвидность или КВ?"

### UC-07. Объяснить, почему продукт подходит или не подходит

**Цель:** дать менеджеру аргументацию, привязанную к данным.

**Примеры запросов:**

- "Почему Fort Knox подходит для краткосрочного размещения?"
- "Почему Unit Linked не основной вариант для сохранения сбережений?"
- "Чем валютный Защищенный капитал отличается от рублевого?"

**Основной сценарий:**

1. Получить продукт и цель клиента.
2. Сопоставить свойства продукта с целью.
3. Вывести 3-5 аргументов и 1-2 ограничения.
4. Сослаться на поля классификатора.

**Пример:** Unit Linked не должен быть первым вариантом для цели "сохранить сбережения", потому что в классификаторе у него указаны `Есть риск` по потере капитала и `Не гарантирован` по доходу. Его можно предлагать только после уточнения готовности клиента к инвестиционному риску.

### UC-08. Получить альтернативы

**Цель:** найти похожие продукты при изменении одного условия.

**Примеры запросов:**

- "Есть похожий продукт, но с высокой ликвидностью?"
- "А есть вариант в валюте?"
- "Покажи продукт без риска, но с налоговыми преференциями"

**Основной сценарий:**

1. Определить исходный продукт или критерии текущего набора.
2. Зафиксировать неизменные критерии.
3. Изменить один целевой критерий.
4. Вернуть альтернативы и пояснить, чем они отличаются.

### UC-09. Выгрузить результат в согласуемом формате

**Цель:** подготовить результат для пересылки или обсуждения.

**Примеры запросов:**

- "Сделай таблицу сравнения в Markdown"
- "Подготовь краткую выжимку по продуктам для клиента"
- "Сохрани подборку в файл"

**Основной сценарий:**

1. Определить формат: Markdown, таблица, Excel, PDF, текст для письма.
2. Собрать найденные продукты и поля.
3. Проверить, какие поля можно показывать клиенту, а какие только внутренним пользователям.
4. Сформировать файл или текст ответа.

### UC-10. Обновить и проверить классификатор

**Цель:** администратор загружает новую версию таблицы и проверяет, что агент корректно ее понимает.

**Основной сценарий:**

1. Загрузить новую таблицу.
2. Определить листы, заголовки, диапазон данных и количество строк.
3. Проверить обязательные колонки.
4. Нормализовать значения: пробелы, регистр, синонимы, числовые поля.
5. Сформировать отчет о качестве данных.
6. Сделать новую версию доступной агенту.

**Контрольные проверки:**

- Нет пустых названий продуктов.
- Все обязательные поля присутствуют.
- Значения в категориальных полях входят в согласованный справочник.
- Для каждого продукта есть ID или правило сопоставления с ID.
- Для клиентских сценариев скрыты поля, не предназначенные для внешнего показа.

## 4. Логика обработки запроса

Базовый алгоритм:

1. Распознать намерение: карточка, комплект, фильтр, сравнение, подбор, объяснение.
2. Извлечь сущности: продукт, срок, валюта, риск, ликвидность, цель клиента.
3. Разрешить неоднозначности через справочник ID, алиасы и семейства продуктов.
4. Применить жесткие фильтры: сегмент, риск, валюта, срок, актуальность.
5. Посчитать ранжирование по мягким критериям.
6. Сформировать ответ с объяснением и ссылкой на версию данных.

## 5. Требования к ответам ассистента

Ответы должны быть короткими, проверяемыми и привязанными к данным:

- указывать, по какой версии классификатора дан ответ;
- показывать основания отбора через поля таблицы;
- не скрывать неоднозначность;
- не утверждать актуальность "на сегодня", если в данных нет статуса актуальности;
- отделять данные классификатора от выводов ассистента;
- задавать уточняющие вопросы только когда без них меняется результат;
- не выводить внутренние поля во внешнем клиентском тексте без бизнес-разрешения.
