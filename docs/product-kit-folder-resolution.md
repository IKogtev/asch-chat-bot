# Алгоритм определения папки комплекта документов продукта

## Назначение

При загрузке активной таблицы продуктов система заполняет для каждого продукта поля:

- `folder_kit` - относительный путь к папке комплекта документов внутри `PRODUCT_KITS_ROOT`;
- `folder_kit_status` - диагностический текст с деталями поиска.

Значения пересчитываются при каждой загрузке таблиц. Если таблицы загружаются заново, старые значения `folder_kit` и `folder_kit_status` не сохраняются.

## Корневая папка

Корень поиска задается переменной окружения:

```text
PRODUCT_KITS_ROOT
```

Актуальные значения:

- локальный дефолт бота: `kb_storage\kb\1 Продукты`;
- `docker-compose` для `bot` и `bot-max`: `/app/kb_storage/kb/1 Продукты`;
- `docker-compose` для `kb-manager`: `/app/data/kb_documents/kb/1 Продукты`;
- Kubernetes для `chatbot`: `/app/kb_storage/kb/1 Продукты`;
- Kubernetes для `kb-manager`: `/app/data/kb_documents/kb/1 Продукты`.

## Алгоритм поиска

На входе для каждой строки таблицы продуктов используются:

- код продукта: колонка `code`, fallback на `id` или `product_id`;
- название продукта: колонка `name`, fallback на `product_name`.

Шаги:

1. Нормализовать код продукта:
   - пробелы по краям удаляются;
   - значения вида `123.0` и `123.00` приводятся к `123`.

2. Рекурсивно обойти все папки внутри `PRODUCT_KITS_ROOT`.

3. Для каждой папки построить полный относительный путь от `PRODUCT_KITS_ROOT`.

   Пример:

   ```text
   Unit Linked (7698)/Unit Linked Ежедневный процент
   ```

4. Найти папки-кандидаты по коду продукта:
   - код ищется не только в имени самой папки, а во всем относительном пути;
   - код должен находиться внутри круглых скобок;
   - поддерживаются составные маркеры, например `(8928+8929)` или `(8965+7698)`;
   - код должен совпадать как отдельное число, чтобы `2832` не совпадал с `12832` или `28320`.

5. Если кандидат один, записать его относительный путь в `folder_kit`.

6. Если кандидатов нет, записать:

   ```text
   не найдена
   ```

7. Если кандидатов несколько, сузить список по названию продукта:
   - название продукта ищется в полном относительном пути кандидата;
   - сравнение выполняется без учета регистра.

8. Если после уточнения по названию найдено совпадение, записать первый совпавший относительный путь.

9. Если кандидатов несколько и уточнение по названию не помогло, записать первый кандидат в сортировке по относительному пути.

10. В `folder_kit_status` записать диагностический текст:
    - код продукта;
    - название продукта;
    - список кандидатов;
    - правило выбора;
    - итоговый результат.

## Примеры

### Код в родительской папке, название во вложенной

Путь:

```text
Unit Linked (7698)/Unit Linked Ежедневный процент
```

Продукт:

```text
code = 7698
name = Unit Linked Ежедневный процент
```

Результат:

```text
folder_kit = Unit Linked (7698)/Unit Linked Ежедневный процент
```

### Составной код

Путь:

```text
Fort Knox/Bundle Fort Knox 6+12 мес. 14%+13,1% (8928+8929) 24.04.26
```

Продукт:

```text
code = 8928
name = Bundle Fort Knox 6+12 месяцев
```

Результат:

```text
folder_kit = Fort Knox/Bundle Fort Knox 6+12 мес. 14%+13,1% (8928+8929) 24.04.26
```

## Скачивание документов

При отправке комплекта бот использует:

```text
PRODUCT_KITS_ROOT / folder_kit
```

Отдаются только файлы, которые лежат непосредственно в найденной папке комплекта.

Вложенные папки внутри комплекта не обходятся, и файлы из них не отправляются.

## Ограничения

- Если папка продукта отсутствует в `PRODUCT_KITS_ROOT`, будет записано `не найдена`.
- Если код продукта в папке указан без круглых скобок, папка не будет кандидатом.
- Если для одного кода есть несколько кандидатов и название продукта не найдено в полном пути, будет выбран первый кандидат по сортировке.
- После изменения структуры папок нужно заново выполнить загрузку таблиц, чтобы пересчитать `folder_kit`.

Команда для пересчета:

```powershell
.\load_tables.ps1
```
